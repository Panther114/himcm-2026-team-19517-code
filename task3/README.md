# Task 3: venue applications

The analysis compares chilled-air cooling at Bayfront and misting at the Medina courtyard. `inputs/` contains scenario and geometry inputs. `src/` contains the matched on/off device-case generation, extraction, and venue analysis. The scripts reuse `../task4/src`; set `HIMCM_ENGINE` if it is located elsewhere. OpenFOAM 12 and the launcher described in the parent instructions are required to run CFD. Python dependencies include numpy, scipy, pandas, shapely 2, pvlib, pyvista, and matplotlib.

Run the physical-invariant checks with `python -m unittest discover -s tests -v`.

`results/venue_maps.npz` and `venue_results.json` are cached outputs of the venue analysis. Reproduce the paper's conditional sensitivity calculation without CFD using:

```
python venue_scale/scripts/make_sensitivity.py
```

Set `HIMCM_TASK3_OUTPUT` to choose its output directory. The calculation changes each input while holding the saved CFD cooling field fixed. The script reports the calculation, including slopes and reference efficiencies.

`venue_scale/scripts/make_figures.py` creates the maps and kernel figures from those results, scenario inputs, and matched CFD kernel files in `results/kernels/`. The latter are omitted due to size, so this script requires generating or supplying those files. `src/run_cases.py` generates cases, `src/extract.py` samples them and `src/analyse.py` combines accepted kernels. `src/figures.py` also needs `results/checks.json`, generated by `src/check_results.py` from the kernels. Those runs require substantial computation; the original case and kernel files are not included. The analysis checks generator hashes and input fingerprints: if the engine differs, regenerate matching kernels rather than bypassing those checks.

`venue_scale/scripts/make_startup_scaled.py` documents the separate start-up calculation, and `venue_scale/figures/efficiency_startup.json` contains its plotted points. It scales fixed steady efficiencies by a single-device transient cooling fraction; Medina is sampled at 3.5 m and Bayfront at 1.1 m. This is not a direct transient whole-venue efficiency calculation. The time-resolved OpenFOAM fields and steady off cases required to rerun it are omitted. Set `HIMCM_TASK3_CASES` to a directory containing the cases named by that script. The start-up script reads `D_fast` and `M_coarse`, prepared by `make_fast_transient.py` and `make_m_coarse.py`. The former also prepares `M_fast`, which is not used in the plotted curve, and defaults to 12 seconds even though the archived Bayfront series extends to 20 seconds; the supplied generator alone does not document that extension. The builders replace their named destination cases when run; `make_fast_transient.py` requires the corresponding steady cases.

The saved venue analysis models 436 Medina fans and treats 94 Bayfront positions as candidates, whereas the paper describes 486 fans and the 94 positions as installed. The sensitivity script gives ambient-temperature slopes of approximately -2.27 and -3.25 percent efficiency per percent change for Bayfront and Medina, respectively. The start-up series is scaled to its last saved time, so it alone does not establish a later equilibrium time.
